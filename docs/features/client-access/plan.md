# F-10 Client access — Implementation Plan (vertical slices)

> **For agentic workers:** `/sdv:build-feature client-access <slice>` runs one slice. Each **step** inside a slice is one commit, test-first. Steps use checkbox (`- [ ]`) syntax; tick them as you go.

**Goal:** a client opens `/g/{token}` with the gallery password, lands on Beranda, picks photos per group (Pilih → Tinjau → Kirim) with notes and print quantities, and later downloads the finished files. The Owner reviews and locks picks, approves add-ons, publishes final delivery, completes the project and rotates the link. The catalog gets a pick mode and a pick-notes flag.

**Approach:** each slice delivers one screen or flow end to end (domain → application → repository → action → UI → tests), can be tried in the browser when done, and produces the data the next slice shows. Order: catalog pick mode → client gate → groups and Beranda → Pilih → Tinjau → Owner review → add-ons → final delivery (Owner) → Hasil akhir (client) → link rotation → cache and hardening.

**Architecture:** see [technical-design.md](technical-design.md) (D-1…D-24). Client access, selection, delivery reads and every client screen in `features/gallery`; add-ons, completion, link rotation and pick mode in `features/booking`; three ADR-016 scopes join them. Client sessions are signed cookies and public limits use the Neon counters ([ADR-021](../../architecture/decisions/ADR-021-client-gallery-sessions-and-public-limits.md)).

**Tech stack:** Next.js 16 (App Router, server actions, route handlers, `next/headers` cookies), React 19, Zod 4, React Hook Form + `zodResolver`, Drizzle on Neon serverless, Tailwind v4 token utilities, react-aria-components (only in `src/ui`), WebCrypto (HMAC-SHA-256), Vitest (unit, dom, integration), Playwright + axe, Storybook.

**Sources:** [design.md](design.md) and [exports/INDEX.md](exports/INDEX.md) (125 exports in 14 folders); [spec.md](spec.md) (A-1…A-34); [acceptance-criteria.md](acceptance-criteria.md); [diagrams/](diagrams/); component specs in `docs/design-system/components/`.

**Base:** `feat/client-access` contains `main` with F-09's free-tier rework (PR #8, migrations up to `0014`). The F-09 units this plan reuses by name: `gallery`, `gallery_photo`, `content_version`, `GalleryBrowseReaderPort`, `directImageUrl`, `serveOwnerPhoto`, `GalleryRateLimiterPort`, `PasswordHasherPort`, `publishGallery`, `PhotoTile`, `FolderTile`, `MediaViewer`, `RotatePasswordDialog`; and from F-07: `editProject`, `addProjectItem`, `updateProjectItemValue`, `removeProjectItem`, `AccessTokenGeneratorPort`, `ProjectDetailScreen` slots, `withProjectCancellationScope`.

## Global Constraints

- **Read the Next.js 16 docs first** for what a slice touches (`node_modules/next/dist/docs/`): route groups with their own root layout, `cookies()` in server actions and route handlers, `notFound()` status, `headers()` in `next.config.ts`, streaming `Response` bodies from route handlers. This Next has breaking changes (AGENTS.md).
- **Checks:** run only the related tests (`npx vitest run <paths>`, one integration file, the slice's E2E spec) plus `pnpm typecheck` and `pnpm lint` on what changed; never the full suite (CLAUDE.md). Never type `head`; use `sed -n`.
- **Lint-clean first time:** functions ≤ 50 lines, cognitive complexity ≤ 15, no inline types in components or use cases, JSDoc on exported functions, copy in `*.copy.ts`, `import "server-only"` in application/adapters/composition; run Prettier and `eslint --fix` per file as you write it.
- **Migrations:** generated by drizzle-kit, reviewed, committed, then `pnpm db:migrate` against the non-production database from `.dev.vars` only; additive only (tech-stack › Deployment). Report each run.
- **UI from exports:** before a screen, read its export(s) one file at a time (names in each slice); map every value to a token; a value without a token is a `DESIGN TOKEN GAP` (report, never hard-code).
- **Secrets:** `CLIENT_SESSION_KEY` must exist in `.dev.vars` before Slice 2 (Owner provisions it; generate with `openssl rand -base64 32 | tr '+/' '-_' | tr -d '='`). Never commit `.dev.vars`/`.env.test`.
- **Never log** a token, the session cookie, a client address, a file or image URL, a password, a hash or ciphertext (D-23).
- **Deviations** from the export, the spec or this plan go into the slice's implementation record at the end of [technical-design.md](technical-design.md).

```ts
// features/gallery/domain/client-session/client-session.ts
import type { ClientSessionPayload, SessionCheckInput } from "./client-session.types";

/**
 * Whether a verified cookie payload still signs this client in (ADR-021, A-1, BR-GAL-003).
 * @param input - the payload, the gallery the token resolves to, the token hash and the clock
 * @returns true only if nothing about the gallery or link changed and the cookie is not expired
 */
export function isSessionValid(input: SessionCheckInput): boolean {
  const { payload, projectId, galleryId, passwordVersion, tokenHash, nowSeconds } = input;
  return (
    payload.v === 1 &&
    payload.exp > nowSeconds &&
    payload.th === tokenHash &&
    payload.projectId === projectId &&
    payload.galleryId === galleryId &&
    payload.pv === passwordVersion
  );
}
```

```ts
// features/gallery/domain/client-gallery-availability/client-gallery-availability.ts
/**
 * Whether a client may open this gallery at all (BR-ACC-001, BR-GAL-005, BR-PRJ-010, A-3).
 * @param input - project status, stored gallery status, expiry and the clock
 * @returns true for a PUBLISHED, unexpired gallery of a project that isn't cancelled
 */
export function isAvailableToClient(input: AvailabilityInput): boolean {
  if (input.galleryStatus !== "PUBLISHED") return false;
  if (input.projectStatus === "CANCELLED") return false;
  return input.expiresAt === null || input.expiresAt.getTime() > input.now.getTime();
}
```

```ts
// features/gallery/domain/selection-usage/selection-usage.ts
import type { PickChange, PickCheck, PickMode } from "./selection-usage.types";

/** BR-SEL-002: never stored. @param base - item value @param extra - approved add-ons @returns the effective limit */
export const effectiveLimit = (base: number, extra: number): number => base + extra;

/**
 * Usage after a pick changes from `currentQuantity` to `nextQuantity` (BR-SEL-003, A-9).
 * @param change - mode, effective limit, current usage and the two quantities
 * @returns OK, LIMIT_REACHED when the new usage would pass the limit, INVALID_QUANTITY otherwise
 */
export function checkPickChange(change: PickChange): PickCheck {
  const { mode, limit, usage, currentQuantity, nextQuantity } = change;
  if (!Number.isInteger(nextQuantity) || nextQuantity < 0) return "INVALID_QUANTITY";
  if (mode === "COUNT" && nextQuantity > 1) return "INVALID_QUANTITY";
  const nextUsage = usage - currentQuantity + nextQuantity;
  // Lowering or removing a pick is always allowed, even when usage is above the limit (A-8).
  if (nextQuantity <= currentQuantity) return "OK";
  return nextUsage <= limit ? "OK" : "LIMIT_REACHED";
}

/** @param mode - pick mode @param quantities - quantities of the group's picks @returns usage */
export function usageOf(mode: PickMode, quantities: readonly number[]): number {
  return mode === "COUNT" ? quantities.length : quantities.reduce((sum, q) => sum + q, 0);
}

/** @param limit - effective limit @param usage - usage @returns places left, never negative */
export const remainingPlaces = (limit: number, usage: number): number => Math.max(0, limit - usage);
```

**Rule code**

```ts
// features/gallery/domain/pick-list/pick-list.ts
import type { PickListEntry, PickMode } from "./pick-list.types";

/**
 * The list the Owner copies (A-6): one line per pick, `× n` for quantity groups, ` — note`.
 * @param mode - the group's pick mode
 * @param picks - picks in file-name order
 * @returns the text to copy, lines joined with "\n"
 */
export function formatPickList(mode: PickMode, picks: readonly PickListEntry[]): string {
  return picks.map((pick) => formatLine(mode, pick)).join("\n");
}

function formatLine(mode: PickMode, pick: PickListEntry): string {
  const quantity = mode === "QUANTITY" ? ` × ${String(pick.quantity)}` : "";
  const note = pick.note ? ` — ${pick.note.replace(/\s*\n\s*/g, " ")}` : "";
  return `${pick.fileName}${quantity}${note}`;
}
```
