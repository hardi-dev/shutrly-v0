Modal
A dialog over a scrim for a focused task (create, edit) or a confirmation. Option A “Sectioned” (Owner 2026-09-26, exploration board 04): header with title, optional description and close; Body slot; Footer slot with actions on surface.subtle. Widths SM 400 · MD 560 · LG 720. Shown in the App Shell’s Overlay layer. Tokens: component.modal.*, button.danger.*.
Component set
Source components. Name = Modal/<Size>; private base _Modal/Base holds the structure and the variants only change width (SM 400 confirm · MD 560 form · LG 720 detail). Fill the Body and Actions slots with Replace on a top-level instance. The masters never include the scrim: the App Shell Overlay layer (C30) owns it.

Usage
A modal interrupts. Use it only when the task must finish (or be cancelled) before the page continues.
• Do: one modal at a time; never open a modal from a modal.
• Do: SM for confirmations, MD for short forms (≤ 5 fields), LG for read-mostly detail. Longer flows get a page.
• Do: actions right-aligned, Cancel (Secondary) then the confirming action; at most one Primary or one Danger.
• Do: Danger only for destructive, irreversible actions; the label repeats the verb (“Hapus proyek”), never “Ya” / “OK”.
• Don't: stack toasts or menus over the scrim; don't put a Table with row actions inside a modal (use a page).
• Mobile (client gallery, GAP-04): use the Bottom Sheet (C32) instead.
Accessibility
WCAG 2.1 AA (C-008); WAI-ARIA dialog pattern.
• role=dialog + aria-modal=true; aria-labelledby = Title, aria-describedby = Description (or the confirm body). Destructive confirms use role=alertdialog.
• Focus moves into the modal on open (first field, or Cancel for a destructive confirm) and is trapped; on close it returns to the trigger.
• Esc and the Close button (aria-label “Tutup”) cancel. Clicking the scrim cancels forms only when nothing was typed.
• Page behind is inert (inert / aria-hidden) and scroll-locked.
• Danger button: white on red.600 4.83 : 1 (light) · near-black on red.400 (dark) meets AA.
