# Auth & Account Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement F-01 so an Owner can register, verify, sign in with password or Google, recover/change a password, update their name, and be blocked safely by status and verification policy.

**Architecture:** Better Auth owns the single identity, credential, session, verification, and reset records. Thin App Router pages/actions call `features/auth` through the composition root; `features/auth` applies Zod validation, rate limits, status/verification policy, and maps typed errors through application-owned ports. Adapters supply Better Auth, Drizzle/Neon, Resend, Cloudflare rate limiting, and Google identity-only integration.

**Tech Stack:** Next.js App Router, TypeScript strict, Better Auth, Drizzle ORM, Neon PostgreSQL WebSocket Pool, Cloudflare Workers/OpenNext, Resend, Google OAuth (`openid email profile`), Zod, React Hook Form, React Aria Components, Tailwind CSS v4, Vitest, Playwright.

## Global Constraints

- Follow `docs/constitution.md`, `docs/coding-rules.md`, `docs/features/auth/spec.md`, `docs/features/auth/acceptance-criteria.md`, and `docs/features/auth/technical-design.md`.
- Do not create a second domain user/owner table; Better Auth's `user` row is the single identity.
- Server-side validation and authorization are authoritative; middleware and client validation are convenience layers only.
- Never log passwords, tokens, cookies, verification/reset URLs, OAuth codes, Google tokens, or raw provider payloads.
- All previews/tests share non-production Neon; tests use unique data and never truncate tables.
- Do not implement final copy until `/sdv:design-feature auth` resolves the copy `SPEC GAP`.
