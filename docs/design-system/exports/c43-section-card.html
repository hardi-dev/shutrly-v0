PATTERN · C43 · LAYOUT · SECTION CARD
Section card
A titled card that groups related content on a page: form fields, a list, a table or an empty state. The header can carry one control on the right, such as a Segmented Control for view tabs, and can be turned off. Default is for desktop and tablet; Compact is for phones; Flush is for lists.
Component set
Name = Section Card/<Density>[/Flush | /No header] · private base _SectionCard/Base. Density: Default (desktop, tablet) · Compact (phone). Content: padded (fields, toggles, empty state) · Flush (list rows). No header: Content only, for a card the page heading already names. Text: Title, Description. Slots: Actions (header, right; empty by default) · Content. Specimen widths 720 / 358; instances fill their column.

Usage
Stack cards in one column: the centered 720 column for settings and forms, the full container for tables and lists.
• Do: separate cards with panel.app.content.gap (28) on desktop and space.6 (24) on phones.
• Do: keep page actions (Simpan perubahan) outside the cards; page-level inline alerts sit above the first card.
• Do: put at most one control in the header Actions slot — a Segmented Control for view tabs or one Secondary / Icon button.
• Don't: nest Section Cards, nest a whole Table or List Card, add elevation, or override header / content insets (SP5).
Accessibility
WCAG 2.1 AA (C-008).
• Render as <section aria-labelledby> pointing to the Title (<h2> under the page <h1>); Description may be aria-describedby.
• A header Segmented Control acts as tabs for the Content: role=tablist, aria-controls the Content region.
• With the header off, give the section an accessible name (aria-label) or rely on the page heading when it is the only section.
• Content components keep their own semantics — labels, errors, list and table roles, focus rings.
